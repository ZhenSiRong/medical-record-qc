# 架构决策记录（ADR）

本目录记录**难以回退或影响面较大的决策**，写成 ADR 而不是散落在对话或注释里。理由：这类决策的价值在于**记录当时的约束与取舍**——后来人看到"为什么这么做"比看到"这么做"更重要，尤其是在约束变化时能判断决策是否还成立。

格式：状态 / 决策日期 / 背景 / 决策 / 理由 / 后果 / 替代方案 / 待定项。文件名 `NNNN-简述.md`，编号不复用。

## 决策一览（按主题）

**AI / 智能能力**
- ADR-0001：智能编码的**部署形态与产品边界**——本地推理、只推荐不落码

**医保支付相关**
- ADR-0002：DRG/DIP 能力的**边界**——不做假分组器、不出具权重；严重度预警做成可替换表

---

## 相关约定

- **凡依赖外部授权件（官方分组器、官方码表、结算权重表）的部分，一律不做假实现**，只做能在自家数据上完成的判断，并把"待官方件到位后替换"写成升级路径。这条出现在 ADR-0002 §3，与 ADR-0001 §4 同源。
- **任何返回医疗支付相关判断的接口，响应体必须带免责声明字段**（沿用 `POST /api/drg-preview` 的 `disclaimer` 模式）。这是接口契约的一部分，不是注释。
