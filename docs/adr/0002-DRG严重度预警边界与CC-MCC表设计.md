# ADR-0002：DRG/DIP 只做「严重度预警」，不出具分组权重

- **状态**：已接受（Accepted）
- **决策日期**：2026-10-09
- **决策人**：项目负责人
- **相关文档**：`docs/research/A2-政策绩效驱动需求.md`（政策依据）、`docs/research/user-match.html`（第 7 项）、[ADR-0001](0001-本地向量召回与LLM精排-for-ICD编码辅助.md)、`mrs-backend/internal/model/intelligence.go`（现行 `drg_group_rule`）

---

## 1. 背景

需求文档把「DRG/DIP 预分组 + 高低编 / CC-MCC 预警」当作**一项**需求（`user-match.html` 第 7 项），现状标记为「部分」，注释写得很准：

> 已实现 15 条示例分组规则与预检接口，可给出分组码、参考权重，以及"未匹配提示"与"高低编风险提示"。但真实分组器涉及数千条 ADRG/DRG 规则、**CC/MCC 排除表与版本管理**，各省权重不同。

**实测现状**（本轮核实）：

| 事实 | 数据 |
|---|---|
| `drg_group_rule` 字段 | `diagPrefix / opPrefix / groupCode / groupName / weight` —— **无严重度维度** |
| 严重度的唯一来源 `otherDiagnosisCodes` | **57 份首页中 0 份填写**（全空） |
| ICD-10 字典 | **24 条**，无任何 CC/MCC 典型编码（无心衰病因、糖尿病并发症、慢性肾病、呼衰等） |
| `otherDiagnosisCodes` 结构 | 单字段逗号分隔字符串，**无"是否作为并发症/合并症"的主次标记** |

## 2. 决策

**把这一项拆成两半：只做「严重度标识的完整性与一致性预警」，不出具分组码与权重。**

| 做 | 不做 |
|---|---|
| CC/MCC **漏编提示**（低靠预警）：其他诊断命中 CC/MCC 但未标记为并发症/合并症 | 官方口径的**分组码** |
| **高靠风险预警**：标记了 CC/MCC，但与主诊断无临床关联 / 属陈旧性疾病 | 结算**权重**与费用预测 |
| 严重度分层预览（本例 = MCC / CC / 无），**明确标注院内口径** | 特例单议判定、0000/QY 组的**金额**折算 |

**依据**：`A2` 第 21 行明确「未按时上传或编码不规范落入 0000 组按 40% 结算；主诊断与主手术不匹配落入 QY 歧义组按 50% 结算」——**这些是医保局结算时算的，我们只能提示风险，不能报数。**

## 3. 为什么这样切（关键论证）

CC/MCC 这个需求里其实捆了**三个独立的东西**，技术上完全不同：

| # | 东西 | 谁能做 | 是否需要官方授权 |
|---|---|---|---|
| ① | **CC/MCC 表**（含排除表：主诊断为某类时该诊断不算 CC/MCC） | 官方发布，与分组器版本绑定 | **需要** |
| ② | **医院编码实践（HCP）内的 CC/MCC 分配** | 同一 CC 编码在 A 医院算 CC、B 医院可能不算，取决于申报惯例 | 不需要，是医院自己的 |
| ③ | **高低编（高靠 / 低靠）** | 本质是**自相矛盾检测** | **不需要** |

**决定性论点：②③ 可以完全在院内数据上完成，且不需要官方权重表。**

- **低靠检测**：病案已录入的其他诊断命中了 CC/MCC 编码，但没被标记为并发症 → 提示核对。这只需要一张表 + 自家数据。
- **高靠检测**：标记了 CC/MCC，但该诊断与主诊断无临床关联或属陈旧性疾病 → 提示审核风险。同样只需自家数据。

而**分组码与权重**必须依赖官方分组器 + 各省权重表——那是授权件的性质，不是实现工作量的问题。

> 这一条与 ADR-0001 的「本地部署」决策同源：**凡依赖外部授权件的部分，一律不做假实现；凡能在自家数据上完成的判断，做扎实。**

## 4. CC/MCC 表：设计决策

**表结构必须做成「可替换 + 版本化」，先塞演示表并显著标注。**

理由：官方表还未取得（见 §6）。若把表内容硬编码进分组逻辑，将来换官方表就要改代码；做成数据表则**只换数据不改代码**。

表的设计要点（实现时细化，本 ADR 锁定形态）：

| 要点 | 取值 |
|---|---|
| 版本绑定 | 表记录归属某个 `version`；不同版本可共存，按当前启用版本查询 |
| 严重度等级 | `MCC` / `CC` / 无（空） |
| 排除规则 | 需要表达"主诊断为 X 类时，Y 不算 CC/MCC"——**这是官方表的核心复杂度**，结构上必须留位 |
| 数据来源标注 | 每条记录标明 `official` / `demo`，**`demo` 数据必须在界面显著标注** |

**强约束**：任何返回严重度判断的接口，响应体**必须**带免责声明字段（沿用 `drg-preview` 已有的 `disclaimer` 模式）。这是接口契约的一部分，不是注释。

## 5. 数据前置：其他诊断的"主次标记"

**问题**：官方分组规则区分「其他诊断」与「**作为并发症/合并症的其他诊断**」。现行 `otherDiagnosisCodes` 是逗号分隔字符串，**表达不了这个语义**。

**决策：新增一个按索引对齐的标记字段，不新建表。**

- 新增 `other_diagnosis_flags`（string），与 `otherDiagnosisCodes` **按逗号位置一一对应**，取值为严重度等级（`0` 无 / `C` CC / `M` MCC）
- **配套硬约束：`otherDiagnosisCodes` 内不允许重复编码**（否则索引对齐无意义）——解析层必须校验并拒绝重复

**为什么不做独立子表**（`front_page_other_diagnosis`）：独立子表在语义上更干净（能表达任意条数与更多属性），但要迁移既有数据、改后端多处、改前端录入。而官方首页规范里其他诊断是**固定上限的编号数据元**（不是无限集合），字符串 + 等长标记串足以表达，且能随 AutoMigrate 平滑加列。

**代价（明确接受）**：等长对齐是"隐式契约"，解析器写错就会错位。**缓解措施**：解析逻辑集中到单个函数 + 表驱动单元测试覆盖（长度不等、含空项、含重复等异常）。**升级触发条件**：若将来需要记录每个其他诊断的更多属性（入院时已有/院内发生、是否作为主诊断等），则改为独立子表。

## 6. 待确认的前提（阻塞"用官方表"这件事，不阻塞预警功能开工）

**设计单位是否持有医保局 2.0 版 CHS-DRG 分组方案 / CC-MCC 表？**

| 情形 | 影响 |
|---|---|
| **有** | 可导入官方表，预警与严重度分层具备结算口径依据 |
| **暂缺 / 没有**（ADR 按此写） | 只能用**演示表**，与现行 `drg_group_rule`（15 条示例规则）性质相同：**必须显著标注"非官方、不得作为结算依据"** |

> ⚠️ **合规红线**：若用自造表出具支付等级判断，性质等同于"用自造规则决定医保支付"——这个风险**高于**技术实现问题。故演示表数据一律标 `demo`，界面与接口双重标注。

## 7. 负面后果（明确接受）

| 后果 | 说明 |
|---|---|
| **没有真实数据，功能无法演示** | 其他诊断当前 **0/57 填写**，且字典里没有 CC/MCC 典型编码。**必须先补种子病案的 CC/MCC 编码**，否则界面永远是空的 |
| 依赖码表规模 | 24 条ICD-10 撑不起严重度分层；此项与「编码库导入 + 真实码表」是**同一前置** |
| 无法验证结算影响 | 没有官方权重表，就无法回答"预警能挽回多少钱"。只能定性说明"避免落入低权重组" |
| 排除表是最难的部分 | 官方排除表逻辑复杂，演示表只能覆盖极少情形，**不能据此认为已具备结算级准确度** |

## 8. 与其他能力的关系（避免重复或冲突）

| 既有能力 | 与新功能的关系 |
|---|---|
| `DIAG_OP_MATCH`（主诊断-主手术匹配） | 防 **QY 歧义组**（按 50% 折付）。**互补不重叠**：它管"配不配"，新功能管"够不够/过不过" |
| `drg_group_rule` 查表预检 | 继续作为**分组提示**保留；新功能在其上**增加严重度维度**，但不产生结算口径结论 |
| 智能编码推荐（ADR-0001） | 上游：推荐辅助编码员填全诊断 → 直接提升 CC/MCC 完整度 |
| 首页质控（`qc_rule`） | CC/MCC 漏编提示**可作为质控规则的一种**（WARN 级，不拦截），复用既有质控闭环与退回返修流程 |

> 最后一条是重要的复用点：**"漏编 CC/MCC"本质上是一种首页质量缺陷**，因此它应该能进现有的质控闭环（退回 → 整改 → 复核），而不是另建一套预警中心。

## 10. 后续验证（补测，不阻塞开工）

1. 低靠检测的准确率：构造"已录入 CC 但未标记"的病案，确认能命中
2. 高靠检测的误报率：构造"标记正确"的病案，确认不误报
3. 索引对齐健壮性：异常输入（长度不等 / 重复编码 / 空项）下的解析行为
