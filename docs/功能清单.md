# 功能清单（全部功能 · 演示覆盖矩阵）

> **本文档的定位**：一张能回答「这系统到底能干什么、哪部分有视频、哪部分只有 API」的完整地图。
>
> **事实来源**（2026-11-06 实测，不是凭记忆写的）：
> - 路由：`mrs-backend/internal/router/router.go` + `handler/branch_ext.go` + `handler/qc_ext.go` + `handler/system.go`（共 **70** 条注册路由）
> - 界面：`frontend/js/components/` 共 **12** 个组件、`frontend/index.html` 单页挂载
> - 规格：`SPEC.md` §1.3 功能域一览、§2.3 功能实现状态（三态）
> - 契约：`mrs-backend/docs/API.md`，双向覆盖测试 `TestApiCoverage` **95/95 = 100%**
>
> **边界声明**：本系统是**教学演示系统**。全部病案数据为虚构数据；CC/MCC 判读表 `Source=demo`，
> **非国家医保局官方表**，仅供编码质控参考，**不作为医保结算或 DRG/DIP 分组依据**。
> DRG/DIP 为「查表版预检」，非官方分组器。

| **待整改质控项** | **0 条** | `GET /qc-results/my-pending`（admin 与 deptuser 均为空） |

> ⚠️ **两个归档率口径不同，别混用**：`81.6%` 是「**在院**病案里已归档的占比」，`40.2%` 是「**出院**病案里已归档的占比」。
> 前者在前端自算（`statistics.js:90`），后者由后端接口给出 —— **同一语义两处定义**，是典型的「第二事实来源」隐患，已登记进 `docs/BACKLOG.md`。

> ⚠️ **「我的待整改」当前无演示数据**：库里没有任何 `handleStatus ∈ {RETURNED, REJECTED_BY_QC}` 的质控项，
> 所以 admin（整改督办）与 deptuser（我的待整改）两个视角的列表**都是空的**。功能本身已实现并有接口，
> 但演示库未激活该状态 —— 汇报时须主动说明，别让观众误以为功能缺失。

## 三、明确不做（边界，汇报时主动说明）

| 事项 | 理由 |
|---|---|
| **官方** DRG/DIP 分组与结算 | 官方分组器与各省权重表需授权获取，超出课程范围。已做的「查表版预检」**不作为结算依据** |
| 无纸化病案 / HIS-EMR 自动采集 | 不接院内临床系统，首页数据由本系统维护 |
| 条码 / RFID 病案示踪 | 仅留架位与流转流水，不做硬件示踪 |
| 服务端分页 | 前端全量加载 + 内存分页（演示规模 ≤ 数百条） |
| 病案复印服务界面 | 真实系统标配，本期仅留 API 位 |
| 工位式三栏布局 | 仅对齐参考实现的**色板**，布局维持卡片式 |
| 真实 LLM 智能编码（批次 3） | 方案已定稿于 `docs/BACKLOG.md`，本期以「规则版预编码」交付 |

## 四、已知缺口（实测确认，非推测）

| # | 缺口 | 影响 |
|---|---|---|
| D3 | 首页条件必填的 4 个字段（外部原因 / 新生儿体重 / 孕周）**前端表单无输入项** | 条件必填规则目前无法在界面触发 |
| D5 | 变更留痕只覆盖首页；编目变更、病案主档变更未留痕 | 《电子病历应用管理规范》要求的「归档后可追溯」只做到一半 |
| D6 | 催缴只是「清单导出」，**无通知动作** | 「每天电话催办 50 次」是调研核心痛点，当前未闭环 |
| D7 | 上报 CSV 为 18 列骨架 | 官方采集项约 90+，现实现 18 列 |
| D8 | 一致性核对用 `updatedAt` + 24h 容忍窗口近似判断「上报后被改」 | 可能误判 |
| D9 | 质量评分口径（100/−15/−5）为自定 | 非官方细则 |
| **D10**（2026-11-06 实测新发现） | **演示库无「已退回待整改」状态的质控项** | 「我的待整改」页 admin / deptuser 两个视角列表均为空，功能已实现但演示库未激活该状态 |
| **D11**（2026-11-06 实测新发现） | **归档率两个口径两处定义**：前端自算「在院病案归档率」81.6%，后端接口给「出院病案归档率」40.2% | 同一语义两处定义，是「第二事实来源」隐患；对外说明须标明口径，否则易被质疑数据矛盾 |
| D12 | 其他诊断错位脏数据在 CC/MCC 检测里静默 | 已 fail-closed 不判读，但暂无 WARN 提示 |
| D13 | 演示判读表仅 16 条前缀 | E11.2/.4/.5/.7、E86、N18.4、T80–T88 等漏检面较大 |
