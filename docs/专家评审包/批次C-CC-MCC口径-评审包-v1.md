## 0. 项目背景（30 秒版）

- 系统：住院病案管理系统（演示项目），覆盖 编目 → 质控 → 归档 工作流。
- 本批做什么：给病案首页质控增加两条 **WARN 级**（提示、不拦截）规则——
  - **低靠（漏编）**：已录入的其他诊断编码命中 CC/MCC 表，但**未标记**为并发症 / 合并症 → 提示编码员核对；
  - **高靠（套高）**：**标记了** C/M（并发症 / 合并症），但编码**不在** CC/MCC 表内、或按排除规则不计 → 提示审核风险。
- 为什么需要专家：CC/MCC 的临床口径与排除逻辑是**领域判断**。机器只能保证「自洽」，不能保证「临床成立」。

### 1.3 判读逻辑（演示形态）

- 前缀匹配，**最长前缀优先**；规则绑定版本，未声明版本的规则不参与判读（fail-closed）；
- 排除规则：主诊断命中排除前缀时，该条**不计** CC/MCC（当前为**单前缀**最简形态）；
- 结果只分三层：MCC > CC > 无。

## 2. 针对性问题（共 7 条）

1. 上表 16 条的「MCC / CC / 不入表」三档划分，按你所了解的编码实践**哪些存疑或应调整**？（我方自重点怀疑：N18.5、I63 与 I69.3 的区分、E11.6 的粒度、I25.1、D63）
2. 两条演示排除（主诊断 C* 时 D63 不计；主诊断 I63* 时 I69.3 不计）在规则层面是否成立？还有哪些**高频合理排除场景**值得进演示表？
3. 「低靠」按「已录码命中 CC/MCC 但被标记为 0」触发——临床上「**已录但正当不作为并发症**」的常见情形有哪些（不属漏编）？我们需要为哪些情形设计降噪 / 豁免？
4. 「高靠」目前只按「标记了 C/M 但码不在表内或被排除」触发——这个机检信号是否过窄？真实的「套高」在首页数据上还有哪些**可机检**的特征？
5. 两条规则定为 **WARN 级（提示、不拦截）** 是否妥当？这类提示在院内现实中应优先推给谁看：编码员 / 临床医生 / 质控办？
6. 从首页质控角度，演示表下一轮**最应补充**的 3–5 个高价值条目（高频病种 × 常见并发症）？
7. 版本口径：我方用 ICD-10（临床版样式）编码 + CHS-DRG 2.0 概念做演示。**结算口径 CC/MCC 表 vs 院内质控口径**在「能做什么、不能做什么」上，最需要提醒我们注意什么？

## 3. 我方现状与已知取舍（诚实标注）

- 演示表 16 条为**自造条目**（每条都标 `demo`），非国家医保局官方表；官方 2.0 版 CC/MCC 表暂未取得 → 界面上会显著标注「非官方、不得作为结算依据」。
- 排除规则只实现了**单前缀**最简形态；官方排除表的多对多 / 按 MDC 分组排除**未实现**。
- 判读结果**不出具**分组码、权重、金额（项目明确的合规边界，不属能力范围）。
- 演示库中病案首页的其他诊断目前填得很少，端到端展示样本有限。
- 我方自认**可能不对**的点（请重点挑战）：N18.5 算 MCC 是否合适；I63 急性期与 I69.3 后遗症的处理粒度；E11.6 是否过窄（E11.5 等怎么算）；I25.1 与 I25.0 的区别；D63 排除前提是否成立。
