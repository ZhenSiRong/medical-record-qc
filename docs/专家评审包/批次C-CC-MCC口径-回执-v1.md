## 一、对 16 条演示条目的判定（对应送审包问题 1）

**先立一条判定原则**：CC/MCC 判的不是「这个病重不重」，而是「该并发症/合并症是否**显著增加本次住院的资源消耗与诊疗复杂度**」。演示表按「疾病种类」划线，作演示可以，但**它不是判定口径**。

| 条目 | 判定 | 我的意见 |
|---|---|---|
| A41 脓毒症 / I21 急性心梗 / I50 心衰 / J96 呼衰 / K72 肝衰竭 / N17 急性肾衰 | MCC | 分档符合临床常识，可作演示 |
| N18.5 慢性肾脏病 5 期 | MCC | 成立（终末期肾病需替代治疗，资源消耗高）；但**必须与 N18.4 划清边界**，演示说明里要写清「分期到位才成立」 |
| I63 脑梗死急性期 | MCC | 成立；且与 I69.3 的区分方向正确 |
| I69.3 脑梗死后遗症 | CC | 成立；「主诊断 I63\* 时不计」的排除演示符合**同一疾病过程不重复计**的思路。缺口：若本次住院针对后遗症做康复（Z50 康复医疗），判定会变化，演示表未覆盖 |
| E11.6 2 型糖尿病伴并发症 | CC | 成立，但**只列 .6 会让 E11.2/.4/.5/.7 全部落空**，低靠检测将大面积漏检 → 建议补条目（见第五节） |
| I25.1 动脉粥样硬化性心脏病 | CC | 可用，但需**前提：本次确实对其诊疗或它确实影响了诊疗**，否则易与陈旧性冠心病混淆 → 建议在 remark 写明前提 |
| I48 房颤 / J44 慢阻肺 / F05 谵妄 / L89 压力性损伤 | CC | 分档大体合理，可作演示 |
| D63 慢性病所致贫血 | CC | 主诊断 C\*（恶性肿瘤）时排除——符合「肿瘤本身表现不计为合并症」的常见做法。缺口：化疗后贫血（D64 等）场景未覆盖 |

**结论**：16 条作为**链路演示**合格；但排除表只做了单前缀，**不得据此认为具备结算级准确度**。

## 二、排除规则的形态（对应问题 2）

- **形态判定正确**：「主诊断命中 X 前缀 → 本条不计」是官方排除表的最简可用近似，方向对。
- **值得补进演示表的高频排除形态**（用于展示，非官方口径）：
  1. 症状/体征码（R 系列）在有明确病因诊断时不计；
  2. 同一疾病过程：急性期 vs 后遗症（已演示 I63/I69.3）、原发灶 vs 转移灶（C77–C79 与 C\* 原发）；
  3. 并发症与其基础病并存（E11.6 与 E11.9 同时出现时的归属）；
  4. 产科：O 系列与 Z37 分娩结局；
  5. 手术/操作相关并发症（T80–T88）与本次手术的关系。
- **重要提醒**：官方排除表本质是**按 MDC/ADRG 分组的多对多关系**，单前缀只能表达一对一。真实上线必须换成官方表并按分组排除。

## 三、「已录但正当不作为并发症」——降噪清单（对应问题 3）

这是**低靠提示最容易误报**的地方。以下情形编码员填「无」是**正确**的，不应提示漏编：

1. **陈旧性 / 既往史**：本次住院未对其做任何诊疗（陈旧性肺结核、恶性肿瘤个人史 Z85 等）；
2. **入院前已存在、对本次诊疗无影响的慢性病**（稳定期慢乙肝携带、轻度白内障等）；
3. **本次仅为评估或排除而检查、最终排除的诊断**；
4. **与主诊断属同一疾病过程的表现**（已由排除规则覆盖）；
5. **产科 / 新生儿的正常生理性条目**（Z37 分娩结局、新生儿生理性黄疸等）。

**降噪建议（转译给实现）**：
- 提示文案必须给出**可忽略 / 可申诉的出口**（例如「如属陈旧性或既往史，请忽略本提示」），不要写成命令式；
- 演示数据里最便宜的代理指标是「该诊断有对应手术操作」或「住院天数与诊疗强度」，但**更稳妥的做法是提示而非判定**；
- **必须保持 WARN 不拦截**——CC/MCC 填报属编码员判断，机器只能提示。

## 四、「高靠」信号是否过窄（对应问题 4）

- 现有信号（标记了 C/M，但编码不构成 CC/MCC 或被排除）本质是**自相矛盾检测**，成立。
- 真实「套高」还包括这些**可机检**的补充信号：
  1. 主诊断与主手术不匹配 → 已有 `DIAG_OP_MATCH`，指向 QY 组；
  2. **其他诊断与主诊断跨 MDC 且被标记为 MCC** → 可用 MDC 分组差异做粗筛（本期建议只做这一条最保守的补充）；
  3. 诊断与医嘱/费用证据不匹配（如诊断重症肺炎但无抗感染用药与呼吸支持）→ 需医嘱数据，本项目暂无；
  4. 把并发症当主要诊断填报 → 已由 `MAIN_DIAG_RULE` 部分覆盖。
- 本期建议：只做①「标记与判定不一致」+ ②「跨 MDC 且标 MCC」的粗筛，其余等官方表与医嘱数据。

## 五、下一轮最应补充的条目（对应问题 6）

按「高频 × 易漏 × 有明确资源消耗」三条筛，优先补 1、4、6：

1. **E11.2 / E11.4 / E11.5 / E11.7**（糖尿病各型并发症）——现表只有 .6，漏检面最大；
2. **N18.4**（CKD 4 期，与 N18.5 的边界）；
3. **J96.0 / J96.9**（急性与慢性呼吸衰竭分层）；
4. **E86**（容量不足 / 脱水）——老年患者高频；
5. **G30 / G31**（认知障碍）与谵妄分型——长期卧床患者高频；
6. **T80–T88**（手术 / 操作相关并发症）——与手术病案强相关，也是高靠敏感区；
7. **K70 / K74**（酒精性肝病 / 肝硬化）与 K72 的边界。

## 六、WARN 定级与推送对象（对应问题 5）

- **WARN 定级妥当**。CC/MCC 填报是编码员判断，机器只能提示；若用 ERROR 拦截病案流转，会引发争议并拖慢归档。
- **推送对象（院内现实）**：
  - 第一责任人：**编码员 / 病案室**（编目与首页质控环节看到）；
  - 第二责任人：**质控办 / 医保办**（按科室做月度汇总与反馈）；
  - 临床医生：只接收「与诊疗事实不符」的核实请求（如确实治疗过却漏编）。
- 本项目演示：落在质控工作台与编目页即可；「按科室月度视角」登记为缺口。

## 七、结算口径 vs 院内质控口径（对应问题 7，最重要）

| 维度 | 结算口径 | 院内质控口径（本项目） |
|---|---|---|
| 来源 | 属地医保部门发布的分组方案与 CC/MCC 排除表，与分组器版本绑定 | 首页填报的完整性与一致性 |
| 用途 | 分组与支付 | 提示编码员核对、教学演示 |
| 可否混用 | **不可混用**——混用即越界 | 同左 |

- **属地差异**：广东地区按病种分值付费（DIF/DIP）与 DRG 的分组逻辑不同，CC/MCC 的处理也不同。本项目用 CHS-DRG 2.0 概念做演示；**真要落地，必须先确认属地医保部门现行文件**（ADR §6 已登记此前提）。
- **合规红线**：任何界面 / 接口输出严重度判断，必须**同时**出现「非官方、不得作为结算依据」的标注与版本 / 来源（Source=demo）。缺一即为越界。
- **不提供**：任何为提高分组、增加支付而调整填报的建议。
