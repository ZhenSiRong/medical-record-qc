## 送审包五件套（必备结构）

1. **评审对象**——界面 / 流程 / 字段 / 规则；能给具体条目就给条目（截图视批次需要）
2. **针对性问题**——≤7 条，问域内判断，不问代码
3. **我方现状与已知取舍**——诚实标注「可能不对的地方」（这是最值钱的部分）
4. **期望输出格式**——发现 / 依据 / 严重度 / 建议动作
5. **边界声明**——不需要审什么（代码实现、性能、我方明确不做的合规边界）

## 回执处理纪律（转译铁律）

每条发现必须落成「**Gherkin 场景 ｜ 质控规则/数据 ｜ ADR ｜ 缺口表**」之一（模式文档 §3.3）；不能落盘的记为「空话」并如实汇报。
