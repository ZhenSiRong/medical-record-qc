一、核心思路：只换数据层，不动界面

前端 8 个页面组件一行不改（除登录改造的 layout.js），把 js/store.js（localStorage 模拟数据）替换为 js/api-store.js：对外仍是同一个 window.MRMS 接口（state / actions / stats / util），内部改走 REST 调 Go 后端，数据真实落 PostgreSQL。统计纯函数从 store.js 原样搬用。

层来源改动
页面组件 ×7 + 图表同事原版零改动
layout.js 外壳同事原版加登录卡片 + 退出按钮
api-store.js 数据层新写REST 拉全量驻留内存 + 状态投影 + 动作链
Go 后端已完成骨架+3 处小增量（见第四节）

二、状态投影表（后端状态机为准，界面显示 demo 中文词）

病案后端状态界面显示
NOT_RECYCLED 未回收未归档
RECYCLED 已回收(待编目)已归档（喂给编目队列，语义与 demo 一致）
CATALOGED / ARCHIVED / BORROWED / SEALED已编目
借阅 / 上报状态界面显示
APPLYING / RETURNED / OVERDUE / REJECTED待审批 / 已归还 / 已逾期 / 已驳回
首页 QC_PASSED → REPORTED待上报 → 已上报
批次 PENDING / SUCCESS / FAILED·PARTIAL待上报 / 已接收 / 已退回

真实六态保留在数据库与 API；投影只是显示层的单向翻译，可随时还原完整状态。

三、动作链映射（demo 一个按钮 = 后端一组真实调用）

界面动作后端调用链
病案登记POST /records + PUT /front-pages（诊断/费用落首页表）
归档（单个/批量）POST /archives/recycle（落归档流水）
编目POST /catalogs + PUT /front-pages + POST /qc（自动质控）+ 自动上架 POST /archives/shelve
借阅「通过」approve + lend 链式（折叠后端两步）；驳回 / 归还各一个 PUT
续借后端新增 PUT /api/borrows/:id/renew
删除病案不删，提示「病案依法不得删除」（合规）
质量等级 甲/乙/丙由真实质控结果推导：无异常→甲，仅 WARN→乙，有 ERROR→丙
新建上报批次按月份收集 QC_PASSED 的 recordIds → POST /report-batches

四、后端小增量（3 处，不影响既有接口）

  1. med_record 加 archived_at / cataloged_at 两列（AutoMigrate 自动加列）——归档日期 / 今日编目数需要真数据
  2. 新增续借端点 PUT /api/borrows/:id/renew
  3. 种子扩充：科室 6→10、医师 4→12、ICD-10 6→24 条、ICD-9-CM3 4→11 条（demo 同款码表）

五、登录与角色

  • 新增登录卡片：账号密码 + admin / deptuser 快捷按钮；顶栏加退出
  • 顶栏与侧栏身份从 /auth/me 回填真实用户
  • deptuser 触发病案室操作时，后端 403 → 前端 toast 提示无权限（权限全在后端，前端零权限代码）
  • token 存 sessionStorage，任意请求 401 自动回登录页

六、工作分解

  • P0打通闭环：api-store 骨架（登录 / 拉数 / 投影）→ 登录页改造 → 登记→归档→编目→借阅→上报全链路真数据落库
  • P1打磨：工作台接 oper_log 真动态、质量等级推导、续借端点、图表真数据核对、种子扩充
  • P2收口：go:embed 前端嵌进单二进制（一个 URL 交付）、CSV 导出列对齐
  • 验收视觉伴侣贯穿：每个里程碑用浏览器实际操作 + 截图核对（登录样式、状态徽章颜色、编目选码联动、图表数据、批次流转）

七、已知取舍（已确认接受）

  • 前端全量内存模型：演示规模上限约数百条（demo 原生形态，不改组件无法服务端分页）
  • 借阅 APPROVED（待借出）中间态被「通过」折叠，不单独展示
  • 病案删除禁用（合规）；pageCount 无后端对应字段，隐藏或固定值
  • 封存 / 架位管理等后端能力暂无界面，仅 API 提供
